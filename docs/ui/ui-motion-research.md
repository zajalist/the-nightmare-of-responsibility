# UI motion research for The Nightmare of Responsibility

Scope: procedural UI materials, UMG animation in production, and combat/animated UI references, mapped to FoA screens. All numbers are from the linked source. Where a number could not be verified it is marked **unverified** or left out. Suggested starting values that come from me, not a source, are marked **(suggested)**.

## (a) UI Material Lab and the User Interface material domain

**What the sample is.** UI Material Lab is Epic's free sample of math-based material functions for 2D UI: 40 material functions, 100+ usage examples, and UMG examples of buttons, progress bars and menus, listed for UE 5.1 ([Marketplace listing](https://docs.unrealengine.com/marketplace/ja/product/ui-material-lab), [tutorial part 1](https://forums.unrealengine.com/t/tutorial-intuitive-material-building-with-the-ui-material-lab-part-1/1139072)). Epic's UEFN health and shield bar tutorial is built from the same functions, which makes it a good worked example ([UEFN health bars](https://dev.epicgames.com/documentation/en-us/uefn/making-custom-health-and-shield-bars-in-unreal-editor-for-fortnite)).

**SDF shapes and anti-aliasing.** Shapes (box, rounded rect, ring, circle) are signed distance fields. The tutorial author recommends replacing `smoothstep` with the lab's anti-aliasing function fed the raw SDF, with a threshold of `0.0` for procedural SDFs and `0.5` for texture-based distance fields. This avoids resolution-dependent edges on low-res platforms ([part 1 thread](https://forums.unrealengine.com/t/tutorial-intuitive-material-building-with-the-ui-material-lab-part-1/1139072)). Stroke thickness is not tied to pixels; the thread suggests tying stroke width to the vertical dimension so it stays stable as width changes (breaks if the widget becomes taller than wide). Pixel-perfect 1 px borders were asked about and not answered.

**GetUserInterfaceUV and Pixel Size.** `GetUserInterfaceUV` outputs the pixel size used to compensate UV scaling, so patterns keep their aspect ratio regardless of widget size. It only works in materials using the User Interface domain; for Surface materials (for example a Widget Component in world space) use a manual X/Y scale instead ([part 3 thread](https://forums.unrealengine.com/t/tutorial-intuitive-material-building-with-the-ui-material-lab-part-3/1139075)).

**Animated fills and progress bars.** The UEFN bars use a scalar `Progress` parameter (name must match exactly), `BGColor` and a fill colour, with `ConstantBiasScale` remapping progress to 0 to 100. The widget binds its Brush through a `Set Scalar Parameter` conversion ([UEFN health bars](https://dev.epicgames.com/documentation/en-us/uefn/making-custom-health-and-shield-bars-in-unreal-editor-for-fortnite)). Common gotcha: creating a Dynamic Material Instance is not enough, it has to be applied to the Image (`Set Brush from Material`) or parameter changes never show ([part 1 thread](https://forums.unrealengine.com/t/tutorial-intuitive-material-building-with-the-ui-material-lab-part-1/1139072)).

**Driving from UMG.** Pattern: User Interface domain, blend mode Translucent if needed, `VertexColor` node so the Image widget's Colour and Opacity tint the material, create the DMI once at construct, keep a reference, then call `SetScalarParameterValue` / `SetVectorParameterValue` on events ([Unreal Garden, UI dynamic materials](https://unreal-garden.com/tutorials/ui-dynamic-materials/)). In the UI domain the outputs collapse to Final Color and Opacity (Emissive becomes Final Color; BaseColor gives nothing) and Shading Model disappears ([forum](https://forums.unrealengine.com/t/using-material-on-umg-images/26037), [EMaterialDomain MD_UI](https://docs.unrealengine.com/4.26/en-US/PythonAPI/class/MaterialDomain.html)). Text blocks have historically rendered translucent parts of a font material as black in some versions ([forum](https://forums.unrealengine.com/t/is-it-possible-to-use-translucent-shader-on-ui-text-material/2014952)), so test M_UI_SandText in the shipping build.

**Retainer Box Phase and PhaseCount.** With Phase 0 and PhaseCount 1 the retainer redraws every frame; PhaseCount 2 redraws every other frame, so a 60 Hz game gets a 30 Hz UI ([URetainerBox PhaseCount, 5.4](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/UMG/Components/URetainerBox/PhaseCount?application_version=5.4)). In 5.x PhaseCount is set at construction and is not modifiable at runtime; `RequestRender()` forces a redraw on demand ([RetainerBox Python API](https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/RetainerBox)). Each retainer owns a render target, so it costs memory and repaint overhead ([Invalidation in Slate and UMG](https://dev.epicgames.com/documentation/en-us/unreal-engine/invalidation-in-slate-and-umg-for-unreal-engine)). A low PhaseCount stutter is also a stylistic tool for the time-shift look.

## (b) UE UI animation in production

**Animation cost ladder (Epic).** From cheapest to most expensive: material-only animation (no CPU cost, GPU only, preferred for looping glows and scrolling backgrounds); Blueprint-scripted tweens without Sequencer (low CPU); UMG Sequencer animations (high CPU, plus a startup cost); animations that change layout (most expensive). Animating non-transform properties like colour forces a repaint; animating render transforms invalidates layout every frame the animation runs, so mark that widget Volatile or keep it short. Use Blueprint tweens for short, frequent things like damage numbers ([Optimization Guidelines for UMG](https://dev.epicgames.com/documentation/en-us/unreal-engine/optimization-guidelines-for-umg-in-unreal-engine)).

**No property bindings, no Tick.** Bound attributes are polled every frame. Epic's guidance is to update on events (for example `OnHealthChanged`) and avoid On Tick and On Paint for UI logic ([Optimization Guidelines for UMG](https://dev.epicgames.com/documentation/en-us/unreal-engine/optimization-guidelines-for-umg-in-unreal-engine)). One root Canvas per HUD or menu is fine; avoid nested Canvas panels and Rich Text where plain Text will do (same page).

**Invalidation.** `Slate.EnableGlobalInvalidation` applies invalidation at window level and disables nested Invalidation Boxes. Invalidation cost order: Volatility/Visibility, Paint (colour, material changes), Layout (size, position, render transform), Child (add/remove children). Try Invalidation Boxes first; add Retainers only if you still need fewer draw calls ([Invalidation in Slate and UMG](https://dev.epicgames.com/documentation/en-us/unreal-engine/invalidation-in-slate-and-umg-for-unreal-engine)). A forum report measured Slate tick going from just over 5 ms to about 3.5 ms after wrapping UI in Invalidation Boxes ([forum summary](https://forums.unrealengine.com/t/optimizing-widget-slate-performance/2693529)); treat that as anecdotal.

**Curves and material tracks in UMG.** UMG animations use the Sequencer Curve Editor for keys and tangents ([Curve Editor docs](https://dev.epicgames.com/documentation/en-us/unreal-engine/animation-curve-editor-in-unreal-engine)), so overshoot and ease-out are authored as tangents, not presets. Older forum threads report that material parameters on a widget could not be curve-edited in a UMG timeline and used a Float Curve plus `SetScalarParameterValue` instead ([forum](https://forums.unrealengine.com/t/can-you-animate-a-dynamic-material-parameter-in-umg-widget-timeline/151529)); verify on 5.8 before relying on either path.

**CommonUI.** `UCommonActivatableWidgetContainerBase` (Stack and Queue) exposes `TransitionType`, `TransitionCurveType` and `TransitionDuration`, and `GetTransitionDuration()` is Blueprint-callable ([API](https://dev.epicgames.com/documentation/unreal-engine/API/Plugins/CommonUI/Widgets/UCommonActivatableWidgetContaine-?application_version=5.3)). Stack transitions are not widget animations and fire no completion event; the workaround is a Delay of `GetTransitionDuration()` ([forum](https://forums.unrealengine.com/t/common-ui-activatable-widget-stack-event-for-transition-animation-complete/2002990/4)). Input routing needs Game Viewport Client Class set to `CommonGameViewportClient`, with actions defined in Input Action Data Tables (`CommonInputActionDataBase` rows) ([CommonUI quickstart](https://dev.epicgames.com/documentation/en-us/unreal-engine/common-ui-quickstart-guide-for-unreal-engine)). All of this is usable from Blueprint.

**Translucency overdraw and material instruction budgets.** Epic's UMG optimisation page does not give numbers for these. Check with the Material Stats panel and `stat slate`; no verified budget figure to cite.

## (c) Production combat and animated UI

**Hit-stop (hitlag).** Smash Bros. Ultimate hitlag is `floor((damage x 0.65 + 6) x multipliers)` frames, capped at 30 frames from Brawl onward (Melee caps at 20); both attacker and victim freeze, and the victim shakes during the freeze ([SmashWiki Hitlag](https://www.ssbwiki.com/Hitlag)). Sakurai describes grounded characters vibrating side to side and airborne ones up and down, and a hard cap so hitstop never exceeds a limit regardless of damage ([Sakurai's Famitsu column, Source Gaming translation](https://sourcegaming.info/2015/11/11/thoughts-on-hitstop-sakurais-famitsu-column-vol-490-1/)). Street Fighter 6 runs at 60 fps; one verified data point is Terry's crouching Medium Punch with hitstop 11 ([SuperCombo wiki, Terry](https://srk.shib.live/w/Street_Fighter_6/Terry/Data)). A full SF6 light/medium/heavy hitstop table and Drive gauge numbers are **unverified** (wiki blocked fetch).

**Screen shake and juice.** Jan Willem Nijman's "The Art of Screenshake" took a dull shooter through about 30 small tweaks, including shaking the screen slightly opposite the direction of fire and a 33% chance of enemies exploding on death ([Game Developer](https://gamedeveloper.com/design/vlambeer-co-founder-shares-advice-on-building-better-action-games); sources disagree on the venue). Jonasson and Purho's "Juice It or Lose It" (GDC Europe 2012) layers tweening, particles, screenshake and sound onto a Breakout clone without adding mechanics ([GDC Vault](https://gdcvault.com/play/1016487/Juice-It-or-Lose)). Neither source gives frame or millisecond values for its tweaks.

**Sekiro posture and parry window.** Default deflect window is 12 frames (0.2 s before the hit). Releasing and re-pressing Guard stacks a penalty down to 4 frames, even 0 if spammed; the penalty clears after 30 frames or immediately on a successful deflect. Consecutive deflects increase posture damage ([Fextralife, Deflection](https://sekiroshadowsdietwice.wiki.fextralife.com/Deflection)). An independent DS Anim Studio measurement also gives 0.2 s / 12 frames ([Nexus Mods article](https://www.nexusmods.com/stellarblade/articles/199)). Some wiki snapshots quote 30 frames; treat 12 as the better-supported figure.

**Damage trail (chip) bars.** The pattern is a second bar behind the main one that holds, then drains toward current health, with the hold timer restarting on every new hit so it does not drain mid-combo ([Roblox DevForum](https://devforum.roblox.com/t/healthbar-damage-effect/1240580)). I found **no developer source** with the Souls/Elden Ring trail delay or drain speed; any ms figure would be invented, so tune it by feel.

**Timing rings and beat sync (Hi-Fi Rush).** Player attacks are automatically adjusted to land on the beat, with extra reward for exact timing, so the rhythm is "more carrot than stick" ([Unreal Engine interview](https://www.unrealengine.com/developer-interviews/hi-fi-rush-was-inspired-by-shaun-of-the-dead-and-futurama), [GamesRadar](https://gamesradar.com/how-hi-fi-rush-came-together-to-deliver-kinectic-action-comedy-inspired-by-edgar-wright-and-shaun-of-the-dead)). The director did the UI design and animation himself to show the link to the music (UE interview). Players can toggle a metronome visualizer ([review](https://laurakbuzz.com/2023/02/02/hi-fi-rush-might-already-be-my-game-of-the-year-2023/)). The game is designed around a stable 60 fps and ships a latency check because audio and visual delay vary by hardware ([Krafton support](https://support.krafton.com/hc/en-us/articles/52370830105625-Hi-Fi-RUSH-Frame-Rate-and-Music-Sync-Information)). GDC talk: "Developing 'Hi-Fi RUSH' Backwards and Finding Our Positive Gameplay Loop", John Johanas; no timing-window ms figures found.

**Persona 5 menus and transitions.** Atlus presented the UI process at CEDEC + KYUSHU 2017: a restricted red palette, central lines to guide the eye, and a dedicated tool for menu character poses ([Siliconera](https://www.siliconera.com/?p=668266)). Hashino says each menu has its own bespoke layout and program, which is why they are expensive to make ([PC Gamer](https://www.pcgamer.com/games/rpg/persona-series-director-says-atluss-flashy-menus-are-actually-really-annoying-to-design), [Kotaku](https://kotaku.com/metaphor-refantazio-persona-5-menu-ui-hashino-1851667088)), and that early P5 menus were hard to read and needed repeated passes ([GamesRadar](https://www.gamesradar.com/games/jrpg/persona-director-and-jrpg-veteran-says-the-amazing-menus-in-metaphor-refantazio-were-really-annoying-to-make-just-as-persona-5s-were-impossible-to-read-at-first)). Lesson: style per screen, legibility pass first.

**Hades.** No primary developer source on Hades hit feedback or boon UI motion was found in budget; only secondary analyses. Not used below.

**Diegetic UI.** Fagerholt and Lorentzon's 2009 Chalmers/DICE thesis "Beyond the HUD" classifies UI as diegetic, non-diegetic, spatial and meta ([DICE slides](https://www2.slideshare.net/DICEStudio/beyond-the-hud-user-interfaces-for-increased-player-immersion-in-fps-games)). Dead Space put all interface into the game world, on the avatar and as holograms ([Game Developer](https://www.gamedeveloper.com/design/game-ui-discoveries-what-players-want); Dino Ignacio's GDC talk [Crafting Destruction](https://gdcvault.com/play/1017723/Crafting-Destruction-The-Evolution-of)). Alien: Isolation's motion tracker blurs the background when raised, so information on the device costs information about the world ([TechRadar](https://www.techradar.com/news/gaming/the-technology-of-fear-how-alien-isolation-will-scare-you-back-to-the-1970s-1267946)); the UI lead called it "a box that feels broken" that has to be aimed ([MCV/Develop](https://www.mcvuk.com/development-news/18-things-we-learned-about-alien-isolation-last-night/)). Metro and Firewatch sources were not checked in budget.

## Mapping to FoA

| Technique | Source game/ref | FoA screen | UE implementation (params, animation, RetainerBox, rough cost) |
|---|---|---|---|
| SDF rounded rect/ring with AA threshold 0.0, aspect fix via GetUserInterfaceUV | UI Material Lab | WBP_SandButton focus frame, WBP_HUD prompt ring | UI domain material; scalars `Radius`, `Stroke`, `Hover`. DMI created once at construct, set on hover/focus events. No retainer. GPU only, no CPU per frame. |
| Hold-to-interact fill | UEFN `Progress` bar | WBP_HUD | Ring SDF masked by angle, scalar `Progress` 0 to 1, set from the hold timer event (not a binding). Cheap; Paint invalidation only. |
| Sand-letter reveal and idle grain | Material-only animation (Epic UMG guidelines) | WBP_Title, WBP_MainMenu | M_UI_SandText scalar `Reveal` keyed in the intro UMG animation (or set by a timeline if 5.8 material tracks misbehave); grain and echo drift run on material `Time`. Zero CPU for the loop. |
| Time-shift echo / datamosh burst on day rollover | Retainer Box effect material, PhaseCount stutter | WBP_HUD rollover overlay | Wrap only the overlay in a Retainer Box with an effect material (scalar `Burst`, `EchoOffset`). PhaseCount 2 for a 30 Hz stutter look (set at construction). One render target; keep it collapsed when idle. |
| Menu push/pop transitions | CommonUI activatable stack; Persona bespoke per-menu motion | WBP_MainMenu to settings, WBP_Pause | `CommonActivatableWidgetStack` with `TransitionType` Fade or Zoom, short `TransitionDuration` (suggested 0.2 s), Delay `GetTransitionDuration()` before focus. Needs `CommonGameViewportClient`. Per-menu intro anim, legibility check first. |
| Prompt punch, overshoot, flash frame | Juice It or Lose It, Art of Screenshake | WBP_HUD prompts, WBP_SandButton press | Prefer a material `Punch` scalar that scales the SDF in UV space (no layout invalidation). If using render transform, a short UMG anim with an overshoot tangent: scale 1.0 to 1.08 to 1.0 over about 0.15 s (suggested), plus a 1 to 2 frame `Flash` scalar to white (suggested). |
| Hit-stop on hit and deflect | Smash hitlag (6 + 0.65 x dmg frames, cap 30), SF6 11-frame example | WBP_Encounter (shirt enemy hits, player deflects) | `Custom Time Dilation` near 0 on player and shirt actors for N frames, so UI keeps animating. Suggested 4 to 8 frames for Lash/Kick, 10 to 14 for CoilStrike and perfect deflect, hard cap. Shirt and HUD bar shake during the freeze. Cost negligible. |
| Screen and UI shake | Vlambeer (shake opposite to the force) | WBP_Encounter | Camera Shake asset on hits, direction opposite the attack. HUD bar nudge as a Blueprint tween on render translation (Layout invalidation for a few frames only). |
| Posture bar | Sekiro posture | WBP_Encounter (shirt enemy) | One bar material, scalar `Posture` growing from centre; event-driven updates; deflect streak raises posture damage like Sekiro. GPU only. |
| Parry window telegraph | Sekiro deflect: 12 frames, penalty to 4/0, resets after 30 frames | WBP_Encounter (Lash, Kick, CoilStrike, Hop) | Shrinking ring SDF around the enemy or prompt, scalar `TimeToImpact` normalised so the ring closes exactly at the hit; window frames shown as a brighter band. Driven from the attack anim notify, not Tick. |
| Damage trail bar | Chip/trail pattern (timing unverified for Souls) | WBP_Encounter player and shirt health | Same material, two scalars `Health` and `Trail`; on hit set `Health`, restart a hold timer, then lerp `Trail` down via a Blueprint timeline. Hold and drain speed tuned by feel, no sourced value. |
| Deflect streak counter | Combo counter pattern, Sekiro streak posture bonus | WBP_Encounter | Text count with the same punch scale and a `Flash` scalar per increment; fade out after the streak breaks. |
| Beat or timing ring and latency offset | Hi-Fi Rush (auto-snap to beat, metronome toggle, latency check) | WBP_Encounter, WBP_Pause settings | Optional ring pulse on the attack rhythm, toggle in WBP_Pause; add an audio/visual offset slider in WBP_Pause. Material scalar `Pulse` set per beat event. Lock to stable frame pacing. |
| Diegetic phone with focus pull | Dead Space (all UI in world), Alien: Isolation tracker blur | WBP_Phone | Widget Component in world space (Surface material path, so no GetUserInterfaceUV); raise the phone and animate camera DoF focal distance onto it while blurring the room. Use manual redraw or a low redraw rate on the component. One render target. |
| Dialog as meta/non-diegetic layer | Fagerholt and Lorentzon taxonomy | Dialog widget | Keep non-diegetic and minimal; fade only, no shake. Event-driven text, Invalidation Box around the static frame. |
| Pause as time freeze | Material-only animation, Global Invalidation | WBP_Pause | Freeze the world, keep a slow echo drift on a material `Time` loop behind the menu. Enable `Slate.EnableGlobalInvalidation` project-wide and mark only animated widgets Volatile. |
